# Публичный выпуск Атласа: оценка на 23 октября 2026

## Вывод

Код пригоден для коммита как рабочая альфа. Публичный сервис и заявка в каталог требуют отдельного этапа подготовки. Текущий приватный экземпляр пользователя нельзя считать общедоступным продуктом. Изменение видимости GitHub не публикует сайт и не подключает пользователей к базе.

Позиционирование: **рабочая память об инструментах для AI-агентов**. Пользователь сохраняет проекты и планы; агент находит подходящие ресурсы и прототипы, проверяет источники и возвращает полезные находки в общую для его клиентов коллекцию. Основная ценность — повторное использование контекста между задачами и агентами.

## Что уже реализовано

- 20 исходных ресурсов, поиск, категории, заметки, избранное, статусы и JSON-экспорт.
- Контекст занятий, проектов, планов и ограничений.
- Горизонты полезности и объяснение связи ресурса с проектом.
- MCP: чтение контекста, поиск, чтение карточки, добавление находки и уточнение описания.
- Изоляция записей по пользователю, дедупликация URL, контроль ревизий.
- Переносимый skill для Codex и Claude Code; проверенный ZIP.
- Семь тестов серверных сценариев, TypeScript и production-сборка прошли. В локальном браузере проверены сохранение контекста после перезагрузки и появление карточки, добавленной через MCP.

Это не подтверждает работу OAuth в реальном Claude, подключение персонального плагина в GPT или готовность публичного многопользовательского сервиса. Новая версия пока не опубликована: запуск помощника публикации остановлен из-за лимита автоматической проверки разрешений.

## Два разных выпуска

### Открытый исходный код

Подготовить отдельный чистый шаблон без привязки к личному Sites-проекту, личного URL и описаний конкретного компьютера. Сохранить рабочий приватный экземпляр. Выбрать лицензию проекта, проверить сторонние notices, описать воспроизводимый запуск нового экземпляра и границу доверия авторизации. Проверить историю перед публикацией. Текущий репозиторий остаётся приватным.

### Публичный продукт / плагин

1. Определить публичный домен и независимый процесс регистрации. Разделить личные базы пользователей; командные рабочие пространства и роли добавлять отдельным этапом.
2. Подтвердить доверенную авторизацию на хостинге и полный вход из GPT и Claude. Вне Sites нельзя доверять присланному клиентом identity-заголовку.
3. Проверить две реальные учётные записи: одна не может читать или изменять данные другой, включая подбор ID, поиск и экспорт.
4. Добавить удаление своих данных, резервное копирование, ограничения нагрузки и наблюдение за ошибками. Зафиксировать, какие данные агент может читать и менять.
5. Подготовить продуктовую страницу, поддержку, описание обработки данных, условия использования, onboarding, демонстрацию и аккаунт с вымышленными данными для проверки.
6. Упаковать MCP и skill в публичный plugin ZIP, пройти проверки и затем подать заявку. Успешная модерация не гарантируется.

## Каталог OpenAI

Официальная документация подтверждает общий каталог плагинов ChatGPT и Codex с поддержкой MCP и skills. Факт существования подтверждён; точную дату недавнего запуска по просмотренным страницам не установили.

Процесс: ZIP → автоматические проверки → review → публикация после одобрения. Для удалённого MCP нужны стабильный HTTPS endpoint, верифицированный издатель, материалы проверки и доступ к тестовой учётной записи, если требуется вход. Требования следует перепроверить перед отправкой.

## Проект сценариев проверки

Ниже сценарии для будущего review, а не утверждение о пройденной проверке в реальных клиентах.

Положительные:

1. Подобрать обработку видео в браузере: поиск возвращает ffmpeg.wasm, полная карточка показывает требования и ограничения.
2. Найти прототип UI для агента: возвращается BoardUI с объяснением применимости.
3. Прочитать контекст и найти ресурс под указанный проект: ответ не придумывает отсутствующие планы.
4. Добавить исследованный ресурс: появляется одна карточка в предложениях с источником, датой и причиной полезности.
5. Уточнить описание: новая версия сохраняется, заметки, статус и избранное не меняются.

Отрицательные:

1. Повторить добавление того же URL: возвращается существующая карточка без дубля.
2. Изменить карточку со старой ревизией или попытаться передать notes в enrichment: операция отклонена, исходные данные сохранены.
3. Прочитать данные без входа либо карточку другого аккаунта: доступ к чужим данным отсутствует.

Следующий конкретный рубеж: развернуть и проверить приватную альфу в обоих клиентах, затем отделить публичный экземпляр. Не публиковать личную коллекцию ради прохождения регистрации плагина.
