# GPT и Claude: доступ к живому Атласу

**Для читателей публичного репозитория:** адреса ниже относятся к приватному экземпляру автора. Для собственной установки замени их адресом своего сервера и пройди его авторизацию. MCP проверен локально; подключение реальных GPT/Claude-клиентов к новой опубликованной версии пока не подтверждено. Открытый исходный код не даёт доступ к базе автора.

Атлас предоставляет MCP-инструменты, а переносимый skill объясняет, когда и как их использовать. Они дают доступ к одной базе пользователя; встроенного чата с оплатой API моделей нет.

## GPT / ChatGPT / Codex

Sites создаёт персональный плагин при публикации MCP-сервера. Найди Атлас в Plugins → Personal → Created by you, выбери Install / Connect. Если инструменты не появились в текущей сессии, начни новый чат. Отдельный локальный MCP-сервер для этого подключения не нужен.

Проверка: попроси вызвать `atlas_get_context`, затем `atlas_search` с запросом `видео`. Ответ должен содержать твой контекст и карточки. Не считай наличие ссылки или установленного skill подтверждением доступа к базе.

## Claude Desktop

Адрес удалённого Streamable HTTP MCP:

```text
https://tool-atlas-kb-oct22.chicguppy1.chatgpt.site/mcp
```

В Claude Desktop открой **Customize → Connectors → Add custom connector**. Назови его Atlas, вставь опубликованный MCP-адрес, затем пройди вход в аккаунт с доступом к базе. В новом разговоре включи Atlas через **+ → Connectors**. Настройки удалённых коннекторов общие с claude.ai. Локальный адрес localhost для этого режима не подходит.

Попроси Claude вызвать `atlas_get_context` и `atlas_search`. Только успешный ответ с твоими данными подтверждает подключение. Вход в сайт сам по себе его не подтверждает. OAuth необходимо проверить в реальном клиенте; не делай личную базу публичной для обхода авторизации.

Официальные инструкции: [подключение remote MCP](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp), [требования к OAuth](https://claude.com/docs/connectors/building/authentication).

Сервер поддерживает `server/discover`, `initialize`, `tools/list`, `tools/call`, `ping` и уведомления инициализации. Он работает без сессий по HTTP POST, отвечает JSON и не предоставляет SSE-поток.

## Навык

Канонический пакет: `skills/atlas-knowledge/`. Готовый ZIP можно скачать из раздела «GPT и Claude» или `public/atlas-knowledge.zip`. Skill не содержит секретов и автоматически рассматривается агентом при подходящих задачах.

- Codex: копия папки `atlas-knowledge` в `~/.codex/skills/`.
- Claude Code: копия в `~/.claude/skills/` для всех проектов либо `.claude/skills/` внутри выбранного проекта.
- Для клиентов с загрузкой skill-архивов используй ZIP, если клиент поддерживает эту возможность.

После установки начни новую сессию. Настройка доступа к MCP и установка skill — отдельные шаги. Один skill без инструментов не даёт доступа к личным данным.

## Рабочий цикл

1. В разделе «GPT и Claude» заполни занятия, текущие проекты, планы и ограничения.
2. Агент читает контекст, ищет решения, получает полные карточки.
3. При разрешённом пополнении агент проверяет первичные источники и добавляет релевантный ресурс.
4. Новая карточка появляется в «От агентов» со статусом «Предложено агентом», горизонтом и объяснением связи с задачами.
5. Пользователь выбирает дальнейший статус. Агент может уточнять описания, сохраняя личные заметки и избранное.

Пример: «Используй Атлас при планировании моего приложения. Найди готовые решения и похожие прототипы. Если встретишь полезный ресурс, проверь источники и добавь его с объяснением, где он пригодится».

Пополнение происходит во время активной сессии агента. Фоновые расписания не созданы. Данные из других проектов не читаются автоматически. Это личная база с рабочими процессами, похожими на корпоративную базу знаний; совместная редактура с ролями команды пока не реализована.

## Доступ и целостность

Личные данные привязаны к ID, который передаёт доверенный шлюз Sites. Сторонний клиент проходит поддерживаемую авторизацию; поля `owner` в аргументах нет. Не размещай этот Worker напрямую в открытом интернете с доверием к произвольным identity-заголовкам.

Поиск возвращает краткие карточки, чтение по ID — полные данные, включая заметки. Запись ограничена авторизованным аккаунтом. Добавление дедуплицирует канонический URL; обновления требуют ревизию. Добавление агентом никогда не перезаписывает совпавшую карточку.

Контекст хранится отдельно от карточек. «Копия контекста» экспортирует его в JSON; обычный экспорт коллекции включает карточки с релевантностью и происхождением, но не контекст. Базовый скрипт `export-baseline.mjs` экспортирует только исходную коллекцию из кода.

## Проекты, решения и обновления

`atlas_get_context` возвращает рабочий контекст и отдельные проекты. `atlas_search` принимает `projectId` и `mode: "topics"` для поиска по темам с объяснением совпадений. Это словарь русских и английских тем, без embeddings и внешнего LLM API.

`atlas_enrich_resource` сохраняет предложение в `pendingUpdate`, не заменяя текущее описание. Открой «От агентов», сравни поля, прими или отклони изменения и сохрани карточку. Личные решения, опыт и проекты агент этим инструментом не изменяет.
